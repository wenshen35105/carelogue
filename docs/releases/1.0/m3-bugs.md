## 二、Bug / 待办清单

### 需要你决定（产品）
1. **"不存储、不用于训练"是替 DeepSeek 做的承诺**（P1，信任问题）：spec §7 的原话已经写进同意弹窗和设置页，但 DeepSeek API 实际的数据保留和训练政策我们没有核实过。自用阶段问题不大；给亲友用之前，需要对照 DeepSeek 的现行条款改写措辞，或改成"Carelogue 不存储"这种只描述我们自己的说法。（Stitch 稿里"脱敏""零留存协议""端到端加密"这类更夸张的说法都没有采用。）**【已决定 2026-09-22】改"责任版"文案（不替服务商承诺、不推责）；服务商条款硬指标见 spec §11。**
2. **"暂不使用"之后的行为**：现在的理解是：同意过就永远不再弹；拒绝之后不记录，下次**主动**点"解释"时再问一次（不同意就没办法解释）。如果你的本意是"拒绝后也永远不再弹，只能去设置里开"，需要改。**【已决定】保持现状（不改）。**
3. **设置页的"数据管理 · 清空所有本地数据"没有做**：Stitch 稿里有这一项，但按"每个设置项都要对应一个已有功能"的原则，目前只有 Profile 页的"清空档案"。如果要做，记住 M2 的教训：删除要显式逐层进行，不能依赖 cascade。**【已决定】做，排入 M4-T25。**
4. **时间线卡片内嵌解释摘要**（design-review 采纳项 1）：M3 的卡里没有安排，目前没做，建议放进 M4。**【已决定】排入 M4-T25。**
5. **Stitch 报告页头的元数据**（孕周、"附件 2 份 (PDF & 影像)"）：没做，属于模板相关字段，Journey 需要保持通用。**【维持不做】**

### 待修（技术）
6. **术语里偶尔混进单位或通用词**（P3）：prompt 已经明确禁止，但真实模型有时还是会列出"mmol/L""参考范围"。可以在客户端加一个过滤（丢掉纯单位或纯通用词），或者接受现状。
7. **解释语言在生成时就固定了**（P3）：用中文生成的结果，切到英文后仍然显示中文，需要手动"重新解释"。可以在结果里记下语言，语言不一致时提示重新解释。
8. **超长 PDF 会被静默截断**（P3）：送给模型的文本上限是 12,000 字，超出部分直接丢掉，没有任何提示。多页报告可以考虑提示"只解释了前 N 页"。
9. **失败重试不受节流限制**（P3，成本）：只有成功的结果才触发 5 分钟节流，失败后可以立即重试。超时的请求可能已经在服务端计费，连续超时时成本不可控。影响很小，先记录。
10. **深色模式下实心杏色按钮对比度偏低**（P3，视觉）：`onAccent` 的暖白字放在深色杏底上（"生成白话解释""同意并继续"），读得清，但对比度一般。
11. **PDFKit 提取的文字会把多行合成一行**（P3）：有些 PDF 生成器写出来的文本层没有换行，模型能读懂，但如果以后要展示原文就需要处理。
12. **开发语言改成了 zh-Hans**：String Catalog 的源语言是中文，导出工具要求两者一致。副作用是：系统语言既不是中文也不是英文的用户，会回落到中文界面。

## 三、需要你本人做的（自动化做不了）
1. **用真实报告跑一次**：产检报告照片 + PDF 各一份，从相册或文件导入到就诊记录，然后点"解释"。真实报告不能 commit 进 repo，所以没有放进自动化测试。真机需要先在设置里填 API Key。
2. **把解释结果给太太读一遍，看她能不能看懂**（T22 验收项）。
3. 真机上的观感（字体渲染、sheet 手感），以及确认"设置 → Carelogue → 首选语言"里能看到中文 / English。模拟器上 per-app language 是通过启动参数验证的。
