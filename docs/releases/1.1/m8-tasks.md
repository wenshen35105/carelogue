## T51 · 求好评（合规版）

- **背景**：上架至今 0 评价；评分/评论是搜索排名与转化信号（ASO 冷启动期尤其重要）。
- **触发（2026-10-11 拍板）**：累计**创建第 5 个 log 后**请求一次——覆盖**全部用户**（原方案"看解释/看总结"仅订阅用户可达，弃用）。
- **节流**：App 侧记录"已请求"，**请求后 90 天内不再请求**（即用户不会被打扰）。注意：弹不弹最终由 iOS 决定，开发者只能控制"请求"的频率；系统另有 365 天 3 次的硬限制。
- **入口**：设置页常驻「喜欢 Carelogue？去评分」→ App Store 评价页深链（`itms-apps://...?action=write-review`）。
- **红线**：不给任何回报/激励（Apple 明文禁止"激励评价"）；不用自定义弹窗假冒系统评分框。
- **验收**：触发路径在模拟器可验证（真实弹窗由系统决定，只在真机出现）；不打扰正常使用流。
- **✅ 代码完成（2026-10-11）**：`Services/ReviewPrompt.swift`——保存**新**记录且库内记录 ≥5、距上次请求 ≥90 天 → 记日期并在编辑器关闭 1.5s 后调 `AppStore.requestReview`；设置页常驻「喜欢 Carelogue？去评分」→ `apps.apple.com/app/id6815909128?action=write-review`。UI 测试 `ReviewPromptUITests`：第 5 条请求、第 6 条不请求、89 天不请求、91 天再请求（模拟器开发构建会真实弹出系统评分框，已截图验证）。
  - CC 自定：「第 5 个 log」按**库内总记录数 ≥5** 判断（老用户已有很多记录 → 下一次新建即请求一次），只在新建时触发，编辑不触发；App Store ID 由 bundle id 查得 `6815909128`。

## T52 · 复诊提醒（本地通知）

- **背景**：backlog「提醒（通知系统）——复诊 / 记录提醒」；本地通知，无需服务器。
- **方案**：
  - 用户开启提醒后调度本地通知；**时间点用户可自定义**（2026-10-11 拍板），默认值：**前一天 19:00 + 当天 08:00**，可改/可增删。
  - 通知内容：就诊名、时间、地点；中英随 app 语言。
  - 权限：**首次设置提醒时**请求通知权限（不在启动时弹）；被拒后设置页给引导文案。
  - 就诊时间修改/删除 → 通知同步重排/取消。
- **验收**：设置提醒后到点收到；改时间/删记录后通知同步；权限拒绝不崩、不影响其他功能。
- **✅ 代码完成（2026-10-11）**：就诊编辑器「提醒 · Reminder」（开关 + 多个「前 N 天 HH:MM」，打开时填入设置页默认值并首次请求权限）；设置页「提醒」卡（默认时间增删改 + 权限关闭引导）；即将就诊卡「已设提醒」pill。调度 = `Services/Reminders.swift`：每次保存/回前台从库里整体重排（改时间/删记录/归档旅程自动同步）。UI 测试 `ReminderUITests`（含真实到点横幅）全绿。
  - CC 自定：提醒只对「进行中」旅程的未来就诊生效；通知点开直达该就诊详情；提醒字段存 `Log.reminderJSON`（随自己 iCloud 同步，不进 CKShare）。
  - 卡外发现（未修，记录）：iOS 17.0 上 `ModelContext.didSave` 不发通知——`ShareChannel` 的「本地保存后 30s 推送」在 17.0 设备上不会触发（回前台仍会同步）。本卡的调度器已同时监听 Core Data 的保存通知规避；ShareChannel 是否同样处理待定。

## T53 · 用药提醒（本地通知）

- **背景**：backlog「用药计划 + 服药提醒」；与 T52 打包成同一套提醒系统。
- **方案**：
  - 新增模型 `Medication`（名称、剂量文本、提醒时间点集合）——**schema 新增**（CloudKit 兼容要点照 CLAUDE.md）。
  - **入口（拍板）**：**全局**（设置/主页一级入口）；每条用药**可选关联一个 journey**（associate）。
  - **频率（拍板，用户视角）**：只做一种交互——「**每天在选定的时间点提醒**」（可加多个时间点，如早晚各一）。它天然覆盖「每日 N 次」与「固定时间点」两种说法；**不做**"每 X 小时"间隔型（与作息冲突、人群小众）。
  - 支持"今天已完成/跳过"的本地记录（不引入服药建议）。
  - **定位纪律**：只提醒"用户自己设的计划"，不提供任何用药建议/相互作用提示（绕开医疗器械边界）。
- **设计稿（2026-10-11）**：`docs/design/stitch/m8-medications/medications/screen.png`（列表）+ `new_medication/screen.png`（表单）。
  - 实现注意：稿中底部 **tab bar 是设计稿发挥，不做**（无全局 tab；入口从设置/主页进）；「今日进度」卡、打卡按钮、快捷 pill（1片/5mg/10ml）、随餐/特别叮嘱字段均为**可选**——v1 先做核心（名称/剂量/多时间点/关联旅程），其余后移。
- **验收**：建一个每天 2 个时间点的药 → 按时收到两次提醒；编辑/停用立即生效；文案中英。
- **✅ 代码完成（2026-10-11）**：新模型 `Medication` + `MedicationIntake`（schema 新增，CloudKit 兼容）；主页「用药」入口卡（今日进度）→ 用药列表（今日进度环、打卡/逐次剂量 chip 已服用·跳过·撤销、下次提醒、暂停/恢复、删除、免责 footer）→ 表单（名称/剂量/多时间点/关联旅程/提醒中开关）；通知带「已服用 / 跳过」动作，点开进用药列表；清空所有数据包含用药。
  - CC 自定：剂量按「次」计数（多时间点的药每个时间点算一次）；每次提醒都是单次通知、滚动排 ≤14 天（已打卡的那次不再响；iOS 64 条上限内，就诊优先），每次打开 app / 保存 / 打卡时重排。⚠️ 若连续两周以上不打开 app 且未点通知动作，之后的提醒会停——对日常用药场景可接受，记入 backlog 观察。

## T54 · Apple Health 集成

- **背景**：测量数据手输麻烦；HealthKit 读写可省事，且是 Apple 生态差异化的第一步。
- **方案**：
  - **读**：体重、血压、心率（以及孕期相关可读项）→ 按用户选择同步进 journey 的测量时间线。
  - **写回 Health（拍板）**：做；用户可关闭，**默认开启**。
  - **前置条件**（三项都办才能上）：
    1. 隐私政策加 **HealthKit 使用章节**（Apple 强制要求，`docs/legal/privacy-policy.md` + 线上 `carelogue.ca/privacy`）；
    2. 隐私标签复核（数据仅设备上处理、不进服务器——"不收集"结论大概率维持，但要重走一遍）；
    3. 权限文案 + 选择性授权（只读用户勾选的类型）。
- **验收**：授权后 Health 里已有的体重出现在时间线；拒绝授权不影响其他功能；写回开关可关。

## T55 · Journey 元数据（通用概要项）

- **背景**：C 区 backlog「Journey 级元数据 chips（预产期 / 血型 / OB）」——要求做成 **generic 机制**，不写死孕期。
- **方案**：
  - Journey 的自定义 **key-value 概要项（chips）**：任意 journey 可加/改/删；展示在 journey 头部。
  - **孕期作为第一套预设模板**：预填「预产期 / 血型 / OB」等——机制通用，内容随模板。
- **验收**：任意 journey 可管理概要项；头部 chip 正常显示；中英。

## T56 · 目标日与进度（通用机制；孕周 tracker 的 generic 化）

- **背景**：C 区 backlog「孕周 tracker」——generic 化为两层。
- **方案**：
  - **① 通用层**：journey 可选设「目标日期」（预产期 / 手术日 / 复查日）→ 头部显示**倒数/进度环**；任意 journey 可用。
  - **② 内容层**：孕期模板的按周内容（"柠檬大小"等里程碑）——**v1.1 先不做**，内容库量大，待 ① 落地后另排。
- **验收**：设目标日期后头部出现进度；清除后消失；无目标日期的 journey 不受影响。
- **设计稿（2026-10-11）**：`docs/design/stitch/m8-journey-header/screen.png`。头部结构 = 标题 + 元数据 chips（预产期/血型/OB…动态）+ 目标日进度环（示例 "65% · 还剩 98 天 · 第 26 周"）+ 其下接现有时间线。
  - 实现注意：稿中"宝贝约 36cm · 760g · 胎动规律"属**孕期内容层**（T56 ②，v1.1 不做）；chips 为动态数据，示例仅示意。

## T57 · 血压双值（收缩压 / 舒张压）

- **背景**：backlog 早标 v1.1；现状核实（2026-10-11）：测量"血压"仅单值（收缩压），代码注释明示"舒张压可写在备注里"——真实缺口。
- **方案**：
  - 血压测量改为**双值**：收缩压 + 舒张压（schema 新增字段，CloudKit 兼容）。
  - 显示统一为 "120/80"（时间线行、详情、趋势图提示语更新）。
  - **趋势图**（已有 `MeasurementChartView`）：血压类型支持**双线**（收缩/舒张）。
  - 旧数据：保留原值（视作收缩压）、舒张压留空；**不做**从备注里解析。
- **验收**：新建血压 → 时间线/详情显示 "120/80"；趋势图双线；旧单值记录正常显示不崩。

## T58 · 主屏 Widget

- **背景**：留存向——一个常驻的主屏存在感；数据从共享容器/SwiftData 读（App Group 或 WidgetKit 的只读快照）。
- **方案（v1 最小）**：
  - 小型/中型 Widget：显示**下次就诊**（名称 + 日期 + 倒计时天数）；无预约时显示最近一条记录或"记录今天"。
  - 点击打开 app 对应位置（深链）。
  - 可选（finalize 定）：中型 Widget 加"快速记录"入口。
- **验收**：预约变更后 Widget 刷新；无数据状态正常；中英；浅/深色。

## T59 · 随手记挂附件

- **背景**：backlog 内测项（M2 #7）；随手记目前不能加照片/文件。
- **方案**：复用现有 Artifact 附件机制——随手记编辑器加附件区（照片/文件），详情页展示；与就诊/报告一致的交互与存储（externalStorage）。
- **验收**：随手记加照片 → 详情可见 → 编辑可删；同步/共享行为与既有附件一致。

## T60 · 地点联想升级（MapKit）

- **背景**：T45 的 type-ahead 目前只从本库历史记录取值；`MKLocalSearchCompleter`（系统框架，iOS 端免费）可联想真实地点（医院/诊所）。
- **方案**：地点输入框联想 = 历史记录（优先）+ MapKit 真实地点补全（去重、限条数）；仍可自由输入；医生字段保持纯历史联想。
- **注意**：联想请求会带"用户输入的查询词"到 Apple（正常范围，不含健康数据）；**离线时降级为纯历史联想**。
- **验收**：输入 "Mount Sinai" 出现真实地点候选；离线正常；选中后存为标准文本。
