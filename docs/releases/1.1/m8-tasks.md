## T51 · 求好评（合规版）

- **背景**：上架至今 0 评价；评分/评论是搜索排名与转化信号（ASO 冷启动期尤其重要）。
- **触发（2026-10-11 拍板）**：累计**创建第 5 个 log 后**请求一次——覆盖**全部用户**（原方案"看解释/看总结"仅订阅用户可达，弃用）。
- **节流**：App 侧记录"已请求"，**请求后 90 天内不再请求**（即用户不会被打扰）。注意：弹不弹最终由 iOS 决定，开发者只能控制"请求"的频率；系统另有 365 天 3 次的硬限制。
- **入口**：设置页常驻「喜欢 Carelogue？去评分」→ App Store 评价页深链（`itms-apps://...?action=write-review`）。
- **红线**：不给任何回报/激励（Apple 明文禁止"激励评价"）；不用自定义弹窗假冒系统评分框。
- **验收**：触发路径在模拟器可验证（真实弹窗由系统决定，只在真机出现）；不打扰正常使用流。

## T52 · 复诊提醒（本地通知）

- **背景**：backlog「提醒（通知系统）——复诊 / 记录提醒」；本地通知，无需服务器。
- **方案**：
  - 用户开启提醒后调度本地通知；**时间点用户可自定义**（2026-10-11 拍板），默认值：**前一天 19:00 + 当天 08:00**，可改/可增删。
  - 通知内容：就诊名、时间、地点；中英随 app 语言。
  - 权限：**首次设置提醒时**请求通知权限（不在启动时弹）；被拒后设置页给引导文案。
  - 就诊时间修改/删除 → 通知同步重排/取消。
- **验收**：设置提醒后到点收到；改时间/删记录后通知同步；权限拒绝不崩、不影响其他功能。

## T53 · 用药提醒（本地通知）

- **背景**：backlog「用药计划 + 服药提醒」；与 T52 打包成同一套提醒系统。
- **方案**：
  - 新增模型 `Medication`（名称、剂量文本、提醒时间点集合）——**schema 新增**（CloudKit 兼容要点照 CLAUDE.md）。
  - **入口（拍板）**：**全局**（设置/主页一级入口）；每条用药**可选关联一个 journey**（associate）。
  - **频率（拍板，用户视角）**：只做一种交互——「**每天在选定的时间点提醒**」（可加多个时间点，如早晚各一）。它天然覆盖「每日 N 次」与「固定时间点」两种说法；**不做**"每 X 小时"间隔型（与作息冲突、人群小众）。
  - 支持"今天已完成/跳过"的本地记录（不引入服药建议）。
  - **定位纪律**：只提醒"用户自己设的计划"，不提供任何用药建议/相互作用提示（绕开医疗器械边界）。
- **验收**：建一个每天 2 个时间点的药 → 按时收到两次提醒；编辑/停用立即生效；文案中英。

## T54 · Apple Health 集成

- **背景**：测量数据手输麻烦；HealthKit 读写可省事，且是 Apple 生态差异化的第一步。
- **方案**：
  - **读**：体重、血压、心率（以及孕期相关可读项）→ 按用户选择同步进 journey 的测量时间线。
  - **写回 Health（拍板）**：做；用户可关闭，**默认开启**。
  - **前置条件**（三项都办才能上）：
    1. 隐私政策加 **HealthKit 使用章节**（Apple 强制要求，`docs/legal/privacy-policy.md` + 线上 `carelogue.ca/privacy`）；
    2. 隐私标签复核（数据仅设备上处理、不进服务器——"不收集"结论大概率维持，但要重走一遍）；
    3. 权限文案 + 选择性授权（只读用户勾选的类型）。
- **验收**：授权后 Health 里已有的体重出现在时间线；拒绝授权不影响其他功能；写回开关可关。

## T55 · Journey 元数据（通用概要项）

- **背景**：C 区 backlog「Journey 级元数据 chips（预产期 / 血型 / OB）」——要求做成 **generic 机制**，不写死孕期。
- **方案**：
  - Journey 的自定义 **key-value 概要项（chips）**：任意 journey 可加/改/删；展示在 journey 头部。
  - **孕期作为第一套预设模板**：预填「预产期 / 血型 / OB」等——机制通用，内容随模板。
- **验收**：任意 journey 可管理概要项；头部 chip 正常显示；中英。

## T56 · 目标日与进度（通用机制；孕周 tracker 的 generic 化）

- **背景**：C 区 backlog「孕周 tracker」——generic 化为两层。
- **方案**：
  - **① 通用层**：journey 可选设「目标日期」（预产期 / 手术日 / 复查日）→ 头部显示**倒数/进度环**；任意 journey 可用。
  - **② 内容层**：孕期模板的按周内容（"柠檬大小"等里程碑）——**v1.1 先不做**，内容库量大，待 ① 落地后另排。
- **验收**：设目标日期后头部出现进度；清除后消失；无目标日期的 journey 不受影响。
