# M6 · 1.0 提交准备（prepare for submission）

> 定位：把 Carelogue 补到「可以提交 1.0」的状态，然后走完提交与上线。
> 结构：① 功能补完（工程卡，本文档）② 真机验收 ③ 提交与上线（执行以 `docs/owner-actions.md` 为准，不在此重复列卡）。
> 原则：测试与提审并行；发布方式手动（过审 ≠ 立即上架）。

## ① 功能补完（发布门槛）

### T38 · 完整导出 / 导入（Full Copy · ~3–4 天 · 第一优先）

- **导出**：全量数据（Journeys / Logs / 附件图片 / 面诊录音）→ 一个数据包（zip：JSON + 附件文件），系统 ShareLink 分享（AirDrop 等）
- **导入**：app 内「导入数据包」→ 重建全部记录（按 UUID 去重合并；附件写回）
- **效果**：她（不同 Apple ID）的手机上拿到与你相同的完整数据，可看可编辑；此后的更新=重新导出导入一次（手动全量同步）
- **注意**：copy 之后两边各自独立——她的改动你看不到；要「两边同一份、自动同步」得等 CKShare（T39）
- **隐私**：数据包为本地文件、AirDrop 直传，不经任何服务器
- 不做（本卡）：增量同步 / 冲突合并精细化（v1.1）；只读快照（已砍）
- 验收：导出孕期全量 → AirDrop 到另一台手机 → 导入后记录/附件/录音完整可用；重复导入不产生重复数据；文案进 String Catalog

### T39 · CKShare 真共享（升级项）

- 一份数据、自动双向同步——她装 app 加入共享；5–6 天工程（+2–3 天迁移尾巴）；双真机两个 Apple ID 测试
- 排期：**紧接 T38 连排**（T38 的导入器 = 本卡第 4 步「回流建本地副本」的地基，不白做）；发布流程并行不受影响；2–3 天迁移尾巴已含（把她的本地副本并进共享）
- 技术背景：`docs/ck-share-study.md`（SwiftData 无官方共享；桥接为社区模式，零件官方、拼法未铺装）

## ② 真机验收
